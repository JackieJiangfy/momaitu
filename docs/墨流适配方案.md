# 墨流 ↔ 墨脉图 适配方案

> **目标**：让墨脉图完整承接墨流的所有创作数据（角色卡 / 世界观 / 叙述者 / 章节 / 状态轨迹 / 伏笔 / 节奏），并在墨流缺失的"角色关系图谱"维度提供自动生成能力，最终实现「墨流创作 → 墨脉图可视化」的端到端闭环，产出质量完美的作品。
>
> **作者**：方案文档 · 2026-08-06
> **适用版本**：墨流 v0.1.0 / 墨脉图（master @ 330466c）

---

## 一、现状分析

### 1.1 墨流 (Moliu) 能力盘点

| 模块 | 数据模型 | 存储 | 核心字段 |
|------|---------|------|---------|
| 角色卡 | `CharacterCard` (Pydantic) | `data/characters/*.yaml` | name / one_line_pitch / speech_profile / speech_samples / inner_voice_style / core(desire/fear/bottom_line) / backstory_summary / backstory_impact / hidden_clues / state(status/location/goal/emotion/physical/resources/known_info) / appearance(height/build/face/hair/outfit/gesture) |
| 世界观 | `WorldSetting` | `data/world/world.yaml` | era / core_rules / power_system / faction_summary / key_constraints / narrative_style |
| 叙述者 | `NarratorCard` | `data/narrator.md` (Markdown) | one_line_pitch / perspective / language_style / daily_tone / climax_tone / emotional_tone / sentence_features / banned_phrases / samples_* |
| 章节正文 | `ChapterResult` | `output/第N章/正文.md` | chapter_num / content / word_count / model_used / tokens_used |
| 章节元数据 | `ChapterMeta` | `data/chapter_NNN/meta.json` | chapter_num / title / word_count / tokens_used / emotion / summary / key_characters / key_events / first_sentence / last_sentence / created_at / updated_at |
| 伏笔 | `ForeshadowEntry` | `data/foreshadow.json` | id / description / status(planted→building→paid/dropped) / planted_chapter / last_advanced / paid_chapter / priority / type(明/暗/潜) |
| 节奏记录 | `RhythmRecord` | `data/rhythm_log.jsonl` | chapter_num / chapter_type / tension_score(1-10) / opening_style / closing_style / dialogue_ratio / has_memorable_moment / emotion_tag |
| 质量报告 | `QualityReport` | 内存 | pre_check / consistency_fatal/warn / reader_want_next / reader_repetitive / tension_score / rhythm_alerts |
| 使用量 | `UsageTracker` | `data/usage_log.jsonl` | monthly_token_budget / 累计 token |
| 角色备份 | `CharacterCard.backup()` | `data/characters/backups/{name}/chNNN_*.yaml` | 每章快照 |
| 记忆/RAG | `MemoryStore` + `Retriever` | `data/memory_db/` (Chroma) | 章节向量+摘要 |

**墨流核心缺失**：
1. ❌ **角色关系模型** — 只有单角色状态，无 A↔B 关系结构
2. ❌ **可视化界面** — 纯 CLI，无法直观查看角色网络
3. ❌ **多用户/多小说隔离** — 单项目本地文件
4. ❌ **关系类型配置** — 无 rel_type / category 体系

### 1.2 墨脉图 (NovelGraph) 能力盘点

| 模块 | 实体 | 表 | 核心字段 |
|------|------|-----|---------|
| 用户 | `SysUser` | sys_user | username / password(BCrypt) / nickname / avatar / status |
| 小说 | `Novel` | novel | title / author / description / cover_url / status |
| 角色 | `NovelCharacter` | novel_character | name / alias / faction / role_type / species / avatar_url / description / first_chapter / power_level / sort_order |
| 关系 | `NovelRelationship` | novel_relationship | source_id / target_id / rel_type / category(pos/neutral/neg) / directed / intensity(1-10) / description / start_chapter / end_chapter |
| 关系类型 | `NovelRelTypeConfig` | novel_rel_type_config | type_name / category / icon / sort_order |

**墨脉图核心优势**：
1. ✅ **关系图谱** — ECharts 力导向可视化，节点拖拽/缩放/点击
2. ✅ **多用户多小说** — MySQL + Sa-Token 鉴权
3. ✅ **关系类型配置** — 每本小说可自定义关系类型
4. ✅ **批量导入导出** — 已实现 JSON 导出

**墨脉图核心缺失（相对墨流）**：
1. ❌ 角色深度字段（核心欲望/恐惧/说话风格/动态状态/外观）
2. ❌ 章节正文与元数据
3. ❌ 世界观 / 叙述者
4. ❌ 伏笔 / 节奏追踪
5. ❌ 角色状态历史轨迹

### 1.3 适配缺口总结

| 维度 | 状态 | 影响 |
|------|------|------|
| 数据通道 | 🔴 完全缺失 | 两系统无法对话 |
| 字段映射 | 🟡 仅 30% 对应 | 墨流 70% 角色信息会丢失 |
| 关系数据 | 🔴 墨流无此概念 | 图谱核心价值无法自动填充 |
| 状态同步 | 🔴 无机制 | 角色状态变化无法反映到图谱 |
| 章节关联 | 🔴 无关联 | 无法按章节追溯关系演变 |

## 二、设计原则

1. **墨流为创作主，墨脉图为视图主**：墨流是 source of truth，墨脉图是只读视图 + 增量分析（关系抽取）
2. **单向推送优先**：墨流 → 墨脉图，避免双向同步的冲突复杂性
3. **字段无损映射**：墨流所有字段都必须在墨脉图找到归宿，不允许丢失
4. **关系自动抽取**：用 LLM 从章节正文抽取关系，墨流无需感知"关系"概念
5. **不破坏墨流现有 CLI**：墨流侧只新增 `mo sync` / `mo sync-relations` 命令，不改动现有流程
6. **墨脉图向后兼容**：扩字段用 NULL 默认值，旧数据不迁移也不报错

## 三、数据模型扩展方案

### 3.1 墨脉图角色表扩展（核心）

**改动表**：`novel_character`（新增 14 个字段，覆盖墨流角色卡全字段）

```sql
ALTER TABLE novel_character
  ADD COLUMN one_line_pitch   VARCHAR(256) DEFAULT NULL COMMENT '一句话定位（墨流）'        AFTER description,
  ADD COLUMN speech_profile   JSON         DEFAULT NULL COMMENT '说话风格（墨流 SpeechProfile）' AFTER one_line_pitch,
  ADD COLUMN speech_samples   JSON         DEFAULT NULL COMMENT '说话样本列表（墨流）'       AFTER speech_profile,
  ADD COLUMN inner_voice_style VARCHAR(512) DEFAULT NULL COMMENT '内心戏风格（墨流）'      AFTER speech_samples,
  ADD COLUMN core_desire      VARCHAR(256) DEFAULT NULL COMMENT '核心欲望（墨流 core.core_desire）' AFTER inner_voice_style,
  ADD COLUMN surface_desire   VARCHAR(256) DEFAULT NULL COMMENT '表层欲望（墨流 core.surface_desire）' AFTER core_desire,
  ADD COLUMN deep_fear        VARCHAR(256) DEFAULT NULL COMMENT '深层恐惧（墨流 core.deep_fear）' AFTER surface_desire,
  ADD COLUMN value_bottom_line JSON        DEFAULT NULL COMMENT '价值观底线列表（墨流）'     AFTER deep_fear,
  ADD COLUMN backstory_summary TEXT         DEFAULT NULL COMMENT '背景摘要（墨流）'          AFTER value_bottom_line,
  ADD COLUMN backstory_impact VARCHAR(512) DEFAULT NULL COMMENT '背景对性格的影响（墨流）'   AFTER backstory_summary,
  ADD COLUMN hidden_clues     JSON         DEFAULT NULL COMMENT '隐藏线索列表（墨流）'       AFTER backstory_impact,
  ADD COLUMN status           VARCHAR(16)  DEFAULT 'active' COMMENT '角色状态：active/injured/missing/dead/left' AFTER hidden_clues,
  ADD COLUMN current_location VARCHAR(128) DEFAULT NULL COMMENT '当前位置（墨流 state.location）' AFTER status,
  ADD COLUMN current_goal     VARCHAR(256) DEFAULT NULL COMMENT '当前目标（墨流 state.current_goal）' AFTER current_location,
  ADD COLUMN current_emotion  VARCHAR(64)  DEFAULT NULL COMMENT '当前情绪（墨流 state.current_emotion）' AFTER current_goal,
  ADD COLUMN physical_state   VARCHAR(128) DEFAULT NULL COMMENT '身体状态（墨流 state.physical_state）' AFTER current_emotion,
  ADD COLUMN resources        JSON         DEFAULT NULL COMMENT '持有资源列表（墨流）'        AFTER physical_state,
  ADD COLUMN known_info       JSON         DEFAULT NULL COMMENT '已知信息列表（墨流）'        AFTER resources,
  ADD COLUMN appearance       JSON         DEFAULT NULL COMMENT '外观详情 height/build/face/hair/outfit/gesture（墨流）' AFTER known_info,
  ADD COLUMN moliu_synced_at  DATETIME     DEFAULT NULL COMMENT '最近一次墨流同步时间'        AFTER appearance,
  ADD INDEX idx_moliu_synced (moliu_synced_at);
```

**字段映射表（完整）**：

| 墨流 CharacterCard 字段 | 墨脉图 novel_character 字段 | 转换说明 |
|------------------------|---------------------------|---------|
| `name` | `name` | 直接 |
| `one_line_pitch` | `one_line_pitch` | 直接 |
| `speech_profile.*` (5 子字段) | `speech_profile` (JSON) | 整体存 JSON |
| `speech_samples[]` | `speech_samples` (JSON) | 数组存 JSON |
| `inner_voice_style` | `inner_voice_style` | 直接 |
| `core.core_desire` | `core_desire` | 拆字段 |
| `core.surface_desire` | `surface_desire` | 拆字段 |
| `core.deep_fear` | `deep_fear` | 拆字段 |
| `core.value_bottom_line[]` | `value_bottom_line` (JSON) | 数组存 JSON |
| `backstory_summary` | `backstory_summary` | 直接 |
| `backstory_impact` | `backstory_impact` | 直接 |
| `hidden_clues[]` | `hidden_clues` (JSON) | 数组存 JSON |
| `state.status` | `status` | 直接（枚举对齐） |
| `state.location` | `current_location` | 直接 |
| `state.current_goal` | `current_goal` | 直接 |
| `state.current_emotion` | `current_emotion` | 直接 |
| `state.physical_state` | `physical_state` | 直接 |
| `state.resources[]` | `resources` (JSON) | 数组存 JSON |
| `state.known_info[]` | `known_info` (JSON) | 数组存 JSON |
| `appearance.*` (6 子字段) | `appearance` (JSON) | 整体存 JSON |
| 推断：`core.surface_desire` 含"变强" | `role_type` | LLM 推断 主角/配角/反派 |
| 推断：`state.location` 中的势力名 | `faction` | 从 WorldSetting.faction_summary 匹配 |
| 推断：无 | `species` | 默认 "人"，玄幻可改 |
| 推断：WorldSetting.power_system | `power_level` | 从 appearance/状态推断等级 |
| 推断：首次出场章节 | `first_chapter` | 从 ChapterMeta.key_characters 反查 |

#### 6.1.1 `mo sync` — 推送全量数据到墨脉图

**用法**：

**实现**（新增 `moliu/cli/sync.py`）：

```python
"""墨流 → 墨脉图 同步命令"""
import asyncio
import json
from pathlib import Path
import typer
import httpx
from moliu.config import Config
from moliu.data.schemas import CharacterCard, WorldSetting, NarratorCard
from moliu.cli.utils import load_characters, load_world, load_narrator


def build_sync_payload(config: Config) -> dict:
    """组装推送数据"""
    data_dir = config.resolve_data_dir()
    output_dir = config.resolve_output_dir()

    # 1. 世界观
    world = load_world(config)
    world_payload = world.model_dump() if world else None
    if world_payload:
        world_payload["raw_yaml"] = (data_dir / "world" / "world.yaml").read_text(encoding="utf-8")

    # 2. 叙述者
    narrator = load_narrator(config)
    narrator_payload = narrator.model_dump() if narrator else None
    if narrator_payload:
        narrator_payload["raw_markdown"] = (data_dir / "narrator.md").read_text(encoding="utf-8")

    # 3. 角色
    characters = load_characters(config)
    char_payloads = [c.model_dump() for c in characters]

    # 4. 章节 + 角色快照 + 节奏 + 质检
    chapters_payload = []
    for chapter_dir in sorted(output_dir.glob("第*章")):
        num = int(chapter_dir.name.removeprefix("第").removesuffix("章"))
        content_path = chapter_dir / "正文.md"
        meta_path = data_dir / f"chapter_{num:03d}" / "meta.json"
        rhythm_path = data_dir / "rhythm_log.jsonl"  # 解析对应行

        if not content_path.exists():
            continue

        chapter = {
            "chapter_num": num,
            "content": content_path.read_text(encoding="utf-8"),
            # ... 解析 meta.json / rhythm 行 / 角色备份 YAML
        }
        chapters_payload.append(chapter)

    # 5. 伏笔
    foreshadow_path = data_dir / "foreshadow.json"
    foreshadows = json.loads(foreshadow_path.read_text(encoding="utf-8")) if foreshadow_path.exists() else []

    return {
        "world": world_payload,
        "narrator": narrator_payload,
        "characters": char_payloads,
        "chapters": chapters_payload,
        "foreshadows": foreshadows,
    }


@app.command()
def sync(
    novel_id: str = typer.Option(..., "--novel-id", help="墨脉图小说ID"),
    base_url: str = typer.Option("http://127.0.0.1:8080/api", "--base-url"),
    token: str = typer.Option(None, "--token", envvar="MO_NOVELGRAPH_TOKEN", help="Sa-Token"),
):
    """推送全量数据到墨脉图"""
    config = load_config()
    payload = build_sync_payload(config)

    async def _push():
        async with httpx.AsyncClient(base_url=base_url, timeout=60) as client:
            headers = {"Authorization": token} if token else {}
            resp = await client.post(f"/novel/{novel_id}/moliu/sync", json=payload, headers=headers)
            resp.raise_for_status()
            return resp.json()

    result = asyncio.run(_push())
    stats = result["data"]["stats"]
    typer.echo(f"[OK] 同步完成:")
    typer.echo(f"  角色: {stats['charactersUpserted']}")
    typer.echo(f"  章节: {stats['chaptersUpserted']}")
    typer.echo(f"  伏笔: {stats['foreshadowsUpserted']}")
```

## 七、关系抽取方案（核心创新）

### 7.1 三层关系发现策略

| 层 | 方法 | 输入 | 输出 | 适用 |
|----|------|------|------|------|
| L1 共现推断 | 章节元数据 `key_characters` 共现 | 多章节的 key_characters | 候选关系对（无类型） | 快速建立初始网络 |
| L2 LLM 抽取 | DeepSeek 分析章节正文 | 单章节正文 + 已知角色列表 | 带 type/category/intensity 的关系 | 关系类型识别 |
| L3 跨章节聚合 | 多章节关系合并去重 | 所有章节的 L2 结果 | 最终关系图谱 | 关系演变追踪 |

### 7.2 L1 共现推断算法

```python
def infer_cooccurrence_relations(chapters: list[ChapterMeta]) -> list[tuple[str, str, int]]:
    """同章出现 ≥3 次的角色对视为有关系"""
    pair_counts = {}
    for ch in chapters:
        for i, a in enumerate(ch.key_characters):
            for b in ch.key_characters[i+1:]:
                key = tuple(sorted([a, b]))
                pair_counts[key] = pair_counts.get(key, 0) + 1
    return [(a, b, n) for (a, b), n in pair_counts.items() if n >= 3]
```

### 7.3 L2 LLM 抽取流程

1. 墨脉图后端拉取章节正文（已同步）
2. 调用 DeepSeek API（复用墨流 gateway 模式）
3. 解析 JSON 数组
4. 按 `(novel_id, source_name, target_name, rel_type)` upsert 到 `novel_relationship`
5. 若 `rel_type` 不在 `novel_rel_type_config` 中，自动新增类型配置

### 7.4 L3 聚合规则

- 同一对角色、同一 `rel_type` 跨章节出现：保留 `startChapter` 最早的，更新 `intensity` 为最大值
- 同一对角色出现不同 `rel_type`：视为关系演变，保留全部记录（如 暗恋→恋人）
- `endChapter` 由 LLM 判断"关系破裂/结束"时填入

### 7.5 关系抽取触发时机

| 触发点 | 模式 | 说明 |
|--------|------|------|
| 墨流 `mo sync` 后自动 | incremental | 仅抽取新同步的章节 |
| 用户在墨脉图 UI 手动 | full / chapter | 选择章节范围重抽 |
| 墨流 `mo sync-relations` | incremental | CLI 显式触发 |

## 八、双向交互流程

### 8.1 推荐工作流（一次性建立）

```
1. 墨流 mo quickstart          → 创建方向/世界观/角色/叙述者
2. 墨流 mo write 1 ...         → 写第1章
3. 墨流 mo write 2 ...         → 写第2章
   ...
4. 墨流 mo write N ...         → 完成 N 章
5. 墨脉图创建小说（UI）        → 拿到 novel_id
6. 墨流 mo link-novel --novel-id <ID>
7. 墨流 mo sync                → 全量推送到墨脉图
8. 墨脉图 UI 触发"关系抽取"    → 自动生成关系图谱
9. 墨脉图 UI 浏览图谱          → 检查角色网络是否合理
10. 墨脉图手动修正关系（可选）  → 调整类型/强度
```

```
墨流 mo write N+1 ...
墨流 mo sync           # 仅推送新章节（幂等）
```

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 墨流角色名与墨脉图已有角色重名 | 同步覆盖旧数据 | upsert 前展示 diff，让用户确认 |
| LLM 关系抽取漏抽/错抽 | 图谱不准 | 提供 UI 手动增删改 + 抽取证据片段可追溯 |
| 章节正文体积大（MEDIUMTEXT） | 数据库膨胀 | 正文压缩存储或单独表，章节列表只查元数据 |
| DeepSeek API 配额耗尽 | 关系抽取失败 | 任务表记录 failed，支持重试 |
| 双向同步冲突 | 数据不一致 | P1 阶段只做单向（墨流→墨脉图），P2 再做反向 |
| 角色卡字段结构未来变化 | 同步失败 | payload 保留 `raw_yaml` 原文，结构变化时可重新解析 |

## 附录 A：墨流角色卡 → 墨脉图 upsert SQL 示例

```sql
INSERT INTO novel_character (
  id, novel_id, name, one_line_pitch, description, backstory_summary,
  core_desire, deep_fear, status, current_location, current_emotion,
  speech_profile, appearance, moliu_synced_at
) VALUES (
  UUID(), 'novel-uuid', '林默', '社恐程序员...', '一句话定位...',
  '8岁父母车祸去世', '掌控自己的人生', '失去在乎的人', 'active', '宿舍512', '紧张',
  '{"style":"简短理性","common_words":["行","嗯"]}',
  '{"height":"178cm","build":"偏瘦"}',
  NOW()
)
ON DUPLICATE KEY UPDATE
  one_line_pitch = VALUES(one_line_pitch),
  backstory_summary = VALUES(backstory_summary),
  -- ... 全字段更新
  moliu_synced_at = NOW();
```

> **注**：`novel_character` 表当前无 `(novel_id, name)` 唯一键，需先 `ALTER TABLE ADD UNIQUE KEY uk_novel_name (novel_id, name, deleted)`。
